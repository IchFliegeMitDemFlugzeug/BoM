# agents.md — Codex task brief (BoM for CATIA: BOM_Extract + ExcelBuilder)

## Контекст
В репозитории есть два VBS-скрипта, работающих связкой:
- `BOM_Extract.catvbs` — извлекает дерево/свойства/массы из CATIA и формирует payload для Excel.
- `ExcelBuilder.vbs` — строит Excel по payload.

Сейчас настройки и словари материалов частично “зашиты” в код. Нужно перевести логику на файлы настроек/библиотеки, лежащие рядом со скриптами.

**Важно (жёсткие требования):**
1) Выполняй задачи строго в порядке: **A1…A9**, затем **B1…B5**.
2) **Не меняй формат payload** (структуры/порядок/разделители/поля) **кроме добавления MAT-строк** (строк типа “материал” для скрытых “БЧ+ткань”).
3) Все файлы (`Settings.txt`, `Code.tsv`, `metals_ru_library.tsv`, `composites_detect_keywords.tsv`) **всегда лежат в одной папке** (workFolder) рядом со скриптами/выходными файлами.
4) Если при сохранении `ExcelBuilder.vbs` он начинает определяться Git’ом как бинарный — **сохраняй его как обычный текст UTF-8** (предпочтительно UTF-8 без UTF-16).
5) “БЧ” ищем **строго в поле Description**, сравнение **без регистра**. Definition остаётся для “наименования”.
6) Поиск “кодов” (в т.ч. `пок`) выполнять **как подстроку** (без регистра). Приоритет: **БЧ важнее всего**.
7) Масса сборки/подсборки всегда включает массу всех элементов, независимо от флагов отображения массы стандартных/ПКИ.

## Блок A — изменения в BOM_Extract.catvbs

### A1. Чтение настроек Settings.txt
- Реализуй чтение `Settings.txt` из `workFolder`.
- Поддержи параметры:
  - `Project_code` (список префиксов через запятую: кириллица и/или латиница)
  - `Repeating_subassemblies_in_tree` (bool)
  - `Non-drawing_parts_as_materials` (bool)
  - `Mass_of_standard_parts` (bool)
  - `Mass_of_pki` (bool)
- Учитывай пробелы/кавычки/регистр (должно быть устойчиво).
- Если файла нет — понятный MsgBox и остановка.

### A2. Project_code → определение “своей” группы
- Переделай проверку “своя деталь/сборка”, чтобы:
  - `PartNumber` startswith любого префикса из `Project_code`
  - сравнение без регистра
- Не использовать захардкоженные `SGTE/СГТЕ`.

### A3. Repeating_subassemblies_in_tree → суммирование подсборок
- Настройка влияет **только на сборки/подсборки**, детали не трогай.
- Если `Repeating_subassemblies_in_tree = false`:
  - одинаковые подсборки суммируются (qty растёт), как “классическая” спецификация.
- Если `Repeating_subassemblies_in_tree = true`:
  - одинаковые подсборки **не суммируются**;
  - каждая встречаемость в дереве даёт отдельную строку подсборки с qty=1;
  - при этом вся иерархия ветки сохраняется (т.е. состав подсборки повторяется).

### A4. Code.tsv → вычисление значения колонки “код” (codeM)
- Загрузи `Code.tsv` из `workFolder`.
- В файле могут быть строки, где пометка/колонка = `description` (это значит: искать по Description).
- Реализуй определение `codeM` по правилам:
  1) Если в `Description` есть “бч” → `codeM = "бч"` (самый высокий приоритет).
  2) Далее: если для какого-то кода в Code.tsv указано `description`, и ключ (код/сочетание) встречается подстрокой в `Description` → ставь этот код (пример: `пок`).
  3) Иначе дефолт:
     - сборка/подсборка → `сб`
     - деталь → `д`
     - (остальные категории оставь совместимыми с текущей логикой проекта, не ломай существующие коды)
- Поиск подстроки — без регистра.

### A5. “БЧ” брать строго из поля Description
- Добавь безопасное чтение `Description` для детали/сборки (аналог SafeGetDefinition).
- Используй `Description` только для:
  - проверки БЧ;
  - поиска кодов по Code.tsv (помеченных `description`).

### A6. Библиотеки материалов вместо хардкода
- Подключи:
  - `metals_ru_library.tsv` (марки/ключи металлов)
  - `composites_detect_keywords.tsv` (ключевые фрагменты для определения композитов/тканей)
- Переделай определение класса материала (“Металл/Композит/Неметалл”) по этим файлам.
- Переделай определение “ткань/армирование” (fabric) по `composites_detect_keywords.tsv`.

### A7. Non-drawing_parts_as_materials (Вариант B) + “только ткани”
Реализуй строго **вариант B**:
- Строки “материал” добавляются **только** для скрытых “БЧ+ткань”, когда `Non-drawing_parts_as_materials=true`.
- Правило скрытия детали:
  - `Non-drawing_parts_as_materials = true`
  - `Description` содержит “бч” (без регистра)
  - материал распознан как ткань/армирование (по composites_detect_keywords.tsv)
- Для таких деталей:
  - строку детали **не выводить** в payload;
  - но её масса должна:
    - входить в массу подсборки/сборки (как и раньше);
    - аккумулироваться в словарь “материал → масса” **внутри текущей подсборки**.
- После того как в подсборке записаны все PART/FAST/PKI, добавь MAT-строки (дочерние строки подсборки) по накопленным материалам:
  - на “G-уровне” должно стоять слово `материал`
  - “Наименование (ЭМ)” = имя материала
  - “код” (codeM) = значение для материала из Code.tsv (обычно `мат`)
  - в колонку “кол-во на 1 борт” (это L в Excel) писать массу в кг с дробной частью (0.37 или 0,37 — допустимо, но лучше как число)
- Важно: MAT-строки не должны удваивать массу сборки (избегай двойного учёта).

### A8. Флаги Mass_of_standard_parts и Mass_of_pki — только отображение
- Масса деталей/сборок считается всегда по модели CATIA (как сейчас).
- Масса сборки всегда включает массу всех элементов.
- Если `Mass_of_standard_parts = true` — отображай массу стандартных изделий в payload; если false — не отображай (поля массы пустые), но в массу сборки она всё равно входит.
- Если `Mass_of_pki = true` — отображай массу ПКИ в payload; если false — не отображай, но в массу сборки входит.
- Не меняй остальные колонки/поля этих строк.

### A9. Самопроверки (минимальные)
Добавь/выполни локальные проверки логики (без “больших” тестов, достаточно sanity):
- Кейс: 5 одинаковых подсборок в крыле → при Repeating=true в payload 5 строк подсборки qty=1; при false — 1 строка qty=5.
- Кейс: БЧ+ткань → строки детали нет, но есть MAT-строка внутри подсборки после PART/FAST/PKI, и масса сборки корректна.
- Кейс: FAST/PKI → масса сборки корректна независимо от флагов отображения.

## Блок B — изменения в ExcelBuilder.vbs

### B1. Data Validation для “код” из Code.tsv
- Загрузить `Code.tsv` из `workFolder`.
- Собрать список значений кодов и повесить выпадающий список (Data Validation List) на колонку “код” (M) для всех строк данных.
- Значения, пришедшие из payload (codeM), должны оставаться выставленными.

### B2. Поддержка MAT-строк как обычных строк payload
- MAT-строки должны корректно писаться в Excel:
  - “G-уровень” = `материал`
  - “Наименование (ЭМ)” = имя материала
  - “код” = `мат`
  - колонка L = масса (кг) с дробной частью, именно как число
- Проверь форматирование чисел (чтобы не превращалось в текст).

### B3. Градиенты серого для строк сборок/подсборок
- Каждая строка сборки/подсборки должна иметь заливку серым:
  - верхние уровни темнее, нижние светлее
- Детали, материалы, стандартные изделия, ПКИ — **без заливки**.
- Заливка на весь диапазон A..Q строки.

### B4. Совместимость с группировкой/иерархией
- Убедись, что Outline/группы и вложенность корректно работают при:
  - повторяющихся подсборках (Repeating=true);
  - появлении MAT-строк в конце подсборки.

### B5. Мини-проверки Excel
- Во всех строках данных в колонке M есть выпадающий список из Code.tsv.
- Заливка серым только у ASM-строк, остальные без заливки.
- MAT-строки стоят после PART/FAST/PKI внутри подсборки и имеют массу в L.
